# SKR-081 meaningful change reports

Status: **done** for the supported local saved-list change-report and opt-in notification acceptance.

Added a deterministic comparison of immutable saved-list revisions. It reports only a changed `current_role` when both revisions contain exactly one reviewed value and the new value has source evidence with an excerpt and source URL. Reports include previous/current literal values, verbatim new-source quote, URL, platform, observation time, and excerpt hash; they label the result as an accepted observation that is not independently verified. The authenticated changes route returns an empty report for the first revision and for same-value refreshes. Conflicting, missing, or suppression-unresolved role values fail closed.

Webhook enqueue now uses that same comparison and queues work only when an enabled, explicitly opted-in endpoint exists and a supported change is present. Snapshot observation timestamps alone do not trigger delivery. The payload remains metadata-only; the consumer fetches the report through the normal authenticated API. Existing webhook worker security, signing, revocation and delivery bounds remain in force. No source, model, user browser, or external receiver was contacted.

Verification: `uv run pytest -q tests/research/test_changes.py tests/db/test_webhooks.py tests/db/test_saved_lists.py tests/db/test_saved_lists_api.py` — **40 passed**. The integration tests cover role transition with new evidence and citation, repeated unchanged refresh without another delivery, outbox delivery behavior, and first/same-value report API responses. Ruff and MyPy passed for changed source files; generated OpenAPI and TypeScript/client contract checks, frontend typecheck, and `git diff --check` passed. Hosted receiver delivery remains subject to the existing SKR-074 release gate.
