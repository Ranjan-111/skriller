# SKR-008 — CI and failure reporting

Implemented backend and frontend GitHub Actions workflows with read-only repository
permissions, bounded job timeouts, fatal checks, pinned Python/Node tooling,
frozen dependency installs, copied-source provenance checks, real PostgreSQL/
RabbitMQ service setup, and always-uploaded JUnit reports. Compose teardown runs
even after failures. Backend path selection includes migrations, infrastructure,
API container files and configuration as well as source and test changes.

The backend runs the offline suite independently of database integration tests.
A separate no-opt-in live collection writes actual skipped test cases to
`.runtime/live-skips.xml`; `SKRILLER_LIVE_TESTS=0` prevents accidental source access.
Configured live tests remain explicitly opt-in local operations with their own
credentials and session prerequisites. Neither workflow supplies credentials or
silently falls back to a live service. Upstream telemetry is disabled.

Web CI runs tests with JUnit output, the actual Next production build, TypeScript
checking, and the web container build. The artifact path explicitly includes
`apps/web`, because upload actions do not inherit a shell working directory.
