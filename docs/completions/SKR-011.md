## Source review and reuse

The supplied Agent-Reach `channels/exa_search.py` inspects mcporter configuration
and explicitly declines to infer remote readiness from it; it has no Brave
request/extraction implementation. `channels/web.py` is a Jina Reader URL reader,
not a search backend. Exa setup guidance contains remote-service claims that were
not treated as tested capabilities or copied into a production guarantee.

The new probe imports `normalize_public_http_url` and `host_matches` directly
from the copied Agent-Reach `utils/url.py`. It therefore reuses actual upstream
URL/domain validation instead of rewriting that logic. HTTP provider parameters,
probe accounting and aggregate evaluation are new glue with no equivalent
implementation identified in the supplied trees.

## Checked official provider facts — 2026-10-12

Brave exposes an independent search index rather than repackaged Google results.
Its pricing page lists Search at **$5/1,000 requests**, with $5 monthly credits;
those are dated published terms, not the user's effective subscription or actual
billed costs. [Brave pricing/index description](https://brave.com/search/api/)

The API documents maximum count **20**, offset **0–9** interpreted as page count,
possible overlap between pages, and query bounds of 600 characters/75 words.
Freshness and country parameters are available; freshness refers to a page's
reported relevant date, not guaranteed entity freshness. [API reference](https://api-dashboard.search.brave.com/api-reference/web/search/post)

`site:`, quoted phrases and exclusions are documented, but the operator page
labels operators experimental. Query syntax does not establish actual enforcement
on a particular corpus. [Operator documentation](https://api-dashboard.search.brave.com/documentation/resources/search-operators)

The public terms restrict durable storage/caching, redistribution and certain
AI-related uses, with exceptions depending on applicable agreements. The pricing
FAQ says result storage needs explicit plan rights and provides no rights to
third-party pages. Confirm the subscribed agreement before storing provider
results, exporting snippets or using them for model evaluation/training.
[API terms](https://api-dashboard.search.brave.com/documentation/resources/terms-of-service),
[Storage and content FAQ](https://brave.com/search/api/)

## Implemented trial

`scripts/probes/search.py` runs only with explicit `--live` and
`SKRILLER_BRAVE_API_KEY`. Without both it makes zero requests and reports skipped.
There is no Google scraping, unconfigured Exa fallback or implicit authentication.
The key is a request header; redirects are refused and response size/time are
bounded. Reports exclude API keys, raw URLs, snippets and provider error bodies.

A fixed three-query corpus targets LinkedIn founder references, Reddit CRM
migration discussions and company-career discovery. The default reads two pages
of ten results per query, for six attempts maximum. It records page offsets,
returned/unique URL counts, duplicate rate, malformed/private URLs, off-domain
results, schema fields and provider operator metadata. Quotations/exclusions are
explicitly documented-not-measured; relevance/completeness is not inferred from
snippets or counts. Domain capability remains false if the operator is ignored,
metadata absent, results empty, lookalike/off-domain or invalid URLs appear.

The report includes an exact-decimal list-price estimate based on attempted calls
(default maximum **$0.030**) and leaves observed billed cost null. Monthly credits,
failed-request billing and customer plan details can change the actual invoice.
Counts measure search references, not validated leads. No overall completeness
claim or final provider decision is produced.

## Zero-cost provider decision after the user declined paid activation

Development selects Exa keyless MCP, already named by the copied Agent-Reach search channel. Official documentation permits getting started without API key/sign-in and states that keyless access is rate-limited; OAuth/API-key modes are separate. [Official Exa docs](https://exa.ai/docs/get-started/exa-mcp). No paid modes or agent_run tool are invoked.

Actual official MCP SDK1.30 trials returned two references each for company, LinkedIn and Reddit queries, in5.940/3.090/3.242seconds respectively. Domain filters retained only matching reference URLs. A preceding SDK trial returned two official company pages in1.940seconds. Metrics are in EXA-KEYLESS.json; raw provider snippets/URLs are not persisted in that report. This is a small feasibility corpus, not qualified-lead accuracy or completeness evidence.

No authenticated billing account/key is attached. Formal Google-style operators, provider pagination and source freshness are not claimed. Current tool schema has no pagination; domain restriction is explicit output post-filtering, not a promise of the provider's operator implementation. Commercial storage/use and broader release quality remain unverified. Brave is not required or awaited for prototype development.

## Current Exa use and production gate — 2026-10-14

The official Exa MCP setup advertises a no-key configuration, while Exa's current Terms grant API use only for documented purposes and prohibit certain redistribution, competitive use, automated extraction, and use outside the documentation. Its current Privacy Policy says query data is used to improve products and technology, including training/fine-tuning models. These public documents do not establish that Skriller's commercial SaaS use, retained/exported search results, or query-data handling is covered by the keyless MCP setup or a customer-specific agreement. This is an unresolved vendor/legal review, not a legal determination.

To avoid an accidental production launch on an unreviewed provider path, production startup now rejects `SKRILLER_SEARCH_PROVIDER=exa_keyless` unless `SKRILLER_SEARCH_COMMERCIAL_TERMS_CONFIRMED=true`; setting search to `disabled` remains available. The research composer also discloses that prompts go to Exa and warns users not to include confidential information or private personal details, with a direct link to the provider policy. The local prototype remains keyless and uses only synthetic/public research prompts. Do not set the production confirmation until the applicable written commercial terms and data handling have been reviewed.
