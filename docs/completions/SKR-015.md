# SKR-015 — Conversations and immutable plans

Added tenant-owned conversation/message/plan schemas and repositories. Plan revisions and messages are protected against UPDATE/DELETE by PostgreSQL triggers, independently of repository code. Refinements append a revision linked to the latest prior plan; composite parent references must belong to the same workspace and conversation. Conversation-row locking serializes revision/message sequence allocation. Prior interpretation JSON retains its original meaning.

Six accumulated PostgreSQL integration tests passed (four tenancy, two conversation tests). Tests verify refinement preserves original interpretation, sequential append-only messages, direct SQL mutation fails, cross-workspace conversation/plan lookup returns unavailable, cross-tenant message insertion is rejected, and stale refinement parents fail. Canonical jobs will reference immutable plan revisions in SKR-017; no Celery cache is involved.

Interface: `ConversationRepository.create(session,title)`, `get(session,conversation_id)`, `add_message(session,conversation_id,role,content)`, `revise_plan(session,conversation_id,interpretation,parent_id=None)`, `get_plan(session,plan_id)`. Inputs use a verified `Database.tenant` session. Responses are row dictionaries/mappings.
