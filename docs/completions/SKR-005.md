# SKR-005 — Dependency lock verification support

Root owns `pyproject.toml`, `uv.lock` and installation. This verification work does not mutate them or the shared environment.

`tests/locking/test_dependency_lock.py` verifies:

- Python 3.12 restriction and local editable sources for all three copied engines in both project configuration and lockfile.
- Locked engine versions match preserved vendor metadata; registry packages have SHA-256 artifact hashes.
- Installed engine modules resolve to the attributed local source directories, with matching distribution versions and editable installation URLs.
- Selected parser, HTTP/browser fetchers, AgentReach, SmartScraperGraph, FetchNode and GenerateAnswerNode import without opening network connections.
- A simulated missing Playwright dependency surfaces an explicit disabled-browser diagnostic through the copied dynamic-import helper; unrelated telemetry remains importable and disabled. This proves helper-level failure handling, not a finished product capability registry.

Checks: 4 dependency verification tests PASS, including all engine subtests. Combined privacy/dependency suite: 10 PASS, 6 subtests PASS, no skips. Ruff passes on both files. The copied telemetry/generation suite has 28 PASS. Combined run: 38 PASS, 6 subtests PASS, 8 upstream dependency deprecation warnings.

Fresh installation from the lockfile must be verified by the root installation workflow; these tests inspect the resulting environment and import closure, and do not independently create another fresh environment. Browser executables and external platform CLIs are separate provisioning requirements; successful Python imports do not claim live browser/platform operation.
