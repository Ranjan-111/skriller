# SKR-069 — bounded workspace execution and manual pilot allowance

Migration 0019 adds forced-RLS trial/pilot policies, immutable per-job admissions and an explicit discarded-outbox timestamp. Trials receive 25 run admissions, at most 25 results and three sources per run. Owner settings can pause execution and lower result/source counts within operator-provisioned ceilings. The authenticated interface shows allowance usage and owner controls before the first research request, with reload and save/error states.

Admission is serialized per workspace and job, with a database trigger independently locking and enforcing the counter. Dispatch rejects blocked/exhausted work without publishing and records a paused reason; cancelled/expired work is not newly admitted. Worker and shared permit_call boundaries check policy again before provider IO and while active calls are monitored. Already-admitted replay does not consume another run. Entitlement-aware request validation rejects oversized counts/custom limits without creating jobs or increasing permitted spend. Cancellation remains available; usage is not refunded/reset on retries or manual allowance revisions.

The application role has no permission to alter tier/operator ceilings or delete admissions. Members may execute/read usage; owner-only settings are enforced by API, application checks and column/RLS permissions. Operator-only scripts/provision_pilot.py provisions a finite manual allowance and reference without billing, provider IO or usage reset. Automated payments/invoicing integrations remain separate P1 billing scope.
