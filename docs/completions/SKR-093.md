# SKR-093 bounded research MCP interface

Status: **done** for the explicit stdio research interface and its listed contract/security acceptance. This does not close hosted or source-account release gates.

Adapted the copied Agent-Reach MCP server/stdio scaffolding with optional trusted product handlers. The default doctor path is preserved and its original tests pass; the product path skips host-wide Config/doctor construction. The patch and exact resulting file hash are recorded in the copied tree's provenance manifest and modification log.

The product tool set is fixed: list conversations, submit source-read research into an existing conversation, read research status/results/plan/usage, list saved lists, read immutable snapshots, and read authorised evidence. Tools have bounded schemas and output. There are no shell, arbitrary URL, credentials, posting/DM, CRM sync, billing, export-destination or source-write tools. Returned source content is labelled untrusted data and is not executed. Submitting research creates ordinary product jobs; the interface is source-read-only, not a promise that research leaves the application's job database unchanged.

One process is bound to a configured API origin/workspace and a private owner token file. The normal API verifies bearer identity and workspace membership on every request. No server-side administrative DB or source credentials are available to MCP. Research uses the actual existing message/job admission path, request idempotency, source switches, budgets and checkpoint worker. The normal message endpoint now accepts an optional explicit workspace query, preventing a workspace-bound client from submitting to another owned workspace. Responses, redirects, API errors, malformed arguments and resource mismatches are bounded/redacted.

Verification: **31 grouped tests passed** across real MCP SDK in-memory protocol, actual authenticated FastAPI/PostgreSQL job admission, a controlled source through the real checkpoint worker, exact normal API results/usage equality, one admission on retry, disabled entitlements, missing auth, another owned workspace, arbitrary tool/extra fields, output bounds, token-file permissions, unchanged upstream doctor behavior and related research/schema/provenance regressions. A separate **actual stdio child process** initialized through the installed MCP client SDK and returned the exact six-tool surface, with no API/source session configured. Ruff and MyPy passed. No user token, browser, external source or model provider was accessed.

See [MCP runbook](../MCP_RUNBOOK.md). The service is optional and was not registered or started in any external client.
