# SKR-071 — source TTL ceilings, stale-citation filtering and durable cleanup

Evidence now receives a bounded source TTL at both storage and repository boundaries: seven days for social/feed/unknown sources, thirty days for web/GitHub/public YouTube, and one hour for private export artifacts. Callers may shorten the TTL but cannot extend its ceiling. Migration 0020 backfills previously indefinite evidence and adds one durable cleanup schedule per registered workspace.

The scheduler claims bounded opaque workspace/actor/lease scopes through a fixed service function; cleanup still requires current tenant membership and matching unexpired lease/actor. It runs each scope through the existing bounded-process helper with a 45-second hard child/process-group budget. Hourly schedules, 60-second recovery leases and transaction-scoped advisory locks make concurrent and repeated deliveries safe. The local stack starts a separate cleanup daemon; it retries database failures without exposing credentials/object keys.

Cleanup selects only expired records in the active tenant, validates private object prefixes, removes blobs, then clears stored pointers/excerpts. Failed deletion preserves the pointer for retry. A crash after physical deletion can repeat safely; obsolete/duplicate leases cannot acknowledge another task. Expired excerpts without blobs are also erased. Audit rows and claim links remain. Result views recheck tenant claim identity/value and current linked evidence, hide stale observations and report the number omitted; export download already rechecks source/artifact expiry. Erasure/suppression and backup deletion replay remain separate SKR-072/073 scope.
