# SKR-027 — URL and network egress boundary

**Implementation ready for integration; operational container/browser gate is
incomplete because Docker Desktop image builds failed with a storage I/O error.**

`src/skriller/security/urls.py` directly reuses the copied/installed Agent-Reach
`normalize_public_http_url` from `third_party/agent-reach/agent_reach/utils/url.py`.
It adds standard-port enforcement, IDNA DNS resolution and rejection of private,
reserved, multicast, IPv4-mapped or mixed public/private answers. No original
helper algorithm was reimplemented or reference/vendor source modified.

`resolve_public_destination(url)` returns an immutable destination with the
vetted numeric addresses. `connect_pinned(destination)` connects directly using
those addresses without a second hostname lookup, closing the DNS-rebinding gap.

`src/skriller/security/proxy.py` provides a bounded HTTP/HTTPS CONNECT forward
proxy. Every request, redirected request or browser subresource reaching it is
validated before dialing. Connections, body sizes, tunnel byte counts and relay
time are bounded; URLs and credential headers are never logged. Private-address
allowances do not exist in production configuration. HTTP request methods are
network transport only; read/write operation policy remains the adapter's job.

`infra/egress` supplies a separate internal worker network, outbound-only proxy
service and Linux worker firewall entrypoint. A worker's only allowed outbound
socket is TCP to the guarded proxy; direct DNS/UDP/QUIC/WebRTC, public/private
IP sockets and loopback TCP are denied independently of proxy environment
variables. Capabilities are dropped after firewall installation. Browser
automation must use pipe transport. The orchestrator owns DB/broker connections
outside this worker network.

## Verification

The combined source security suites initially passed **24 tests**, including
real loopback HTTP forwarding, redirect-to-metadata denial, private subresource
HTTP denial and private HTTPS CONNECT denial. DNS tests cover mixed/private/
mapped/multicast answers and pinned-address connection without another lookup.
Tests inject a local upstream connection **after** real public validation;
production has no fixture URL exception or configurable private allowlist.

Final combined rerun before cleanup-result hardening: **25 passed, 1 explicit
container gate skipped**. The hardened runner's final separate suite passed
**8 tests**; effective combined coverage is 26 passing tests and one unverified
container gate. Ruff check/format and unchanged Agent-Reach provenance pass.

The opt-in container boundary test in
`tests/security/test_container_boundary.py` checks real direct-socket denial,
proxy-only connectivity, zero effective capabilities, absent host-only files
and a read-only root filesystem. It is skipped by default, not counted as a
passed isolation check. Browser end-to-end integration must additionally verify
the selected engine's proxy/pipe configuration.

Both proxy and worker image builds failed while writing Docker Desktop's
`/var/lib/docker/buildkit/containerd-overlayfs/metadata_v2.db` with
`input/output error`. No user containers, images, volumes or builder state were
pruned/restarted. Thus kernel firewall and container/browser runtime operation
have **not** been verified on this host. Do not run fetch workers without this
boundary or mark all production fetch paths covered until deployment and engine
integration gates pass.

Base image is pinned to the manifest digest resolved by the attempted build.
Proxy supports direct public internet egress only; upstream residential proxy
chaining is not implemented. DNS resolution uses the OS resolver and its
timeouts; the proxy caps concurrent requests but does not yet supply a custom
DNS deadline. Deploy it only on the internal worker network, without a public
host listener.
