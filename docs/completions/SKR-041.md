# SKR-041 — access-scoped response freshness (provisional)

Implemented `src/skriller/connectors/cache.py` around the actual copied `scrapling.spiders.cache.ResponseCacheManager.get/put` from `third_party/scrapling`. Upstream filesystem replay operations run only in private temporary staging; no replacement response serializer was written. Cookies and all request headers are removed before the copied serializer executes. Response headers are limited to bounded content type, ETag and Last-Modified values. The reviewed fetch logging guard also prevents copied response constructors logging private URLs.

Canonical replay bytes use existing private `EvidenceStorage` with content digest and expiry; existing tenant-scoped `entities` hold one cache pointer per identity. The key includes workspace, source, canonical URL, entity type, extraction version, schema hash and opaque connection reference/access mode. No global public or private cache is configured. PostgreSQL conflict handling updates a pointer only for a newer collection timestamp, preventing late old responses from replacing newer content. Stored evidence remains immutable; old evidence rows/blobs remain available for the separate retention lifecycle. No migration or source snapshot patch was required.

Connection-backed reads and writes check current workspace membership, connection source, active/unexpired state and read scope without decrypting credentials. Reads repeat this check after replay; revocation during replay fails closed. Expired entries miss instead of becoming current evidence. Storage verifies the serialized envelope digest before copied decoding, and the wrapper verifies the decoded body digest and bounds. Cache retrieval preserves its original collection time and independent optional publication time. `published_since` returns unknown for unavailable publication timestamps; `claim_is_fresh` uses the claim's independent verification date. A cache hit cannot renew an old role claim.

Conditional cache reads support an expected content hash. `conditional_headers` selects a validated ETag or Last-Modified header only while the authorized entry remains fresh. It performs no network request and does not extend TTL. HTTP 304 revalidation/renewal is deliberately not asserted as implemented by this adapter.

Verification: `pytest -q tests/db/test_response_cache.py tests/db/test_storage.py` — **9 passed**, actual PostgreSQL restricted-role transactions, private filesystem blobs and actual copied cache operations. Covers upstream roundtrip, credential/header exclusion, tenant and distinct connection isolation, schema/version keys, conditional hash/headers, TTL expiry, old publication versus recent collection, expired role claims, digest tampering, late old collection, expired/revoked connections and revocation during replay. Ruff and mypy passed. Upstream lxml deprecation warnings remain visible.

Remaining gates: production collector/pipeline lookup/store integration, source-specific cache policy approval, deployment access controls and live S3 verification inherited from dependencies; physical expiry cleanup belongs to SKR-071. Cache bodies must only enter this internal adapter from a trusted source route declaring its actual access context. Generic evidence download routes must not expose replay envelopes without the same access checks. No live website, credentials, browser session or external API was used. Full-ticket done status is not justified yet.
