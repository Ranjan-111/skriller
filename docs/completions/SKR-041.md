# SKR-041 — access-scoped response freshness (provisional)

Implemented `src/skriller/connectors/cache.py` around the actual copied `scrapling.spiders.cache.ResponseCacheManager.get/put` from `third_party/scrapling`. Upstream filesystem replay operations run only in private temporary staging; no replacement response serializer was written. Cookies and all request headers are removed before the copied serializer executes. Response headers are limited to bounded content type, ETag and Last-Modified values. The reviewed fetch logging guard also prevents copied response constructors logging private URLs.

Canonical replay bytes use existing private `EvidenceStorage` with content digest and expiry; existing tenant-scoped `entities` hold one cache pointer per identity. The key includes workspace, source, canonical URL, entity type, extraction version, schema hash and opaque connection reference/access mode. No global public or private cache is configured. PostgreSQL conflict handling updates a pointer only for a newer collection timestamp, preventing late old responses from replacing newer content. Stored evidence remains immutable; old evidence rows/blobs remain available for the separate retention lifecycle. No migration or source snapshot patch was required.

Connection-backed reads and writes check current workspace membership, connection source, active/unexpired state and read scope without decrypting credentials. Reads repeat this check after replay; revocation during replay fails closed. Expired entries miss instead of becoming current evidence. Storage verifies the serialized envelope digest before copied decoding, and the wrapper verifies the decoded body digest and bounds. Cache retrieval preserves its original collection time and independent optional publication time. `published_since` returns unknown for unavailable publication timestamps; `claim_is_fresh` uses the claim's independent verification date. A cache hit cannot renew an old role claim.

Conditional cache reads support an expected content hash. `conditional_headers` selects a validated ETag or Last-Modified header only while the authorized entry remains fresh. It performs no network request and does not extend TTL. HTTP 304 revalidation/renewal is deliberately not asserted as implemented by this adapter.

Verification: `pytest -q tests/db/test_response_cache.py tests/db/test_storage.py` — **9 passed**, actual PostgreSQL restricted-role transactions, private filesystem blobs and actual copied cache operations. Covers upstream roundtrip, credential/header exclusion, tenant and distinct connection isolation, schema/version keys, conditional hash/headers, TTL expiry, old publication versus recent collection, expired role claims, digest tampering, late old collection, expired/revoked connections and revocation during replay. Ruff and mypy passed. Upstream lxml deprecation warnings remain visible.

Remaining gates: production collector/pipeline lookup/store integration, source-specific cache policy approval, deployment access controls and live S3 verification inherited from dependencies; physical expiry cleanup belongs to SKR-071. Cache bodies must only enter this internal adapter from a trusted source route declaring its actual access context. Generic evidence download routes must not expose replay envelopes without the same access checks. No live website, credentials, browser session or external API was used. Full-ticket done status is not justified yet.

## Public collector integration — 2026-10-14

The earlier pipeline-lookup blocker is superseded for public web pages. collection_cache.py invokes the actual copied scoped cache before guarded HTTP collection; successful unchanged-URL static responses populate it after cleanup validation. SKRILLER_PUBLIC_RESPONSE_CACHE_TTL_SECONDS is opt-in, bounded to0–300 seconds. Account/platform routes, redirects and browser renderings stay outside this policy. Hits are reclassified, retain original collection dates, charge zero fetch attempts and never renew claims. Expiry causes an ordinary accounted fetch. Cache writes repeat persisted cancellation/deadline/access and source-switch checks after serialization under the privacy fence. Replay repeats deletion suppression and access before returning; suppressed URLs receive no conditional validators. Journal fetches at most1001 rows before its existing pilot limit.

Verification: 48 passed, two opt-in live cases skipped across collection/cache/erasure/fetch/page extraction. New PostgreSQL/loopback tests cover repeated jobs, dates, accounting, expiry, workspace isolation, warm-cache disable, cancellation during serialization and erasure during replay. ## Sol public HTTP 304 revalidation — 2026-10-16

The public collection path now revalidates entries carrying ETag or Last-Modified during the second half of their original fresh TTL. It reuses the copied Scrapling HTTP engine and guarded proxy, with the same job capacity, deadlines, per-URL attempt limit and fetch reservation. Validators are bounded and exact-scope: same workspace, job, public source URL and verified body hash. Redirect destinations do not inherit validators for another URL. An unsolicited, mismatched or late 304 fails closed. A changed 200 follows the normal new-body path.

A valid 304 reuses the private, digest-verified body and retains its original collection date and expiry; the validation timestamp is separate metadata. It does not renew a source claim or cache TTL. Persisted cached-body and metadata evidence retain that expiry. After expiry, collection performs an ordinary full fetch. No expired replay retrieval was added, and authenticated/platform caching remains outside this public policy.

Verification: 7 new real PostgreSQL/guarded-loopback cases; the first combined HTTP/cache/collection selection passed 45 with one opt-in live skip. The final changed-code selection passed 54 with one opt-in live skip across cache/collection/repair/resume (overlapping groups are not additive). Tests cover actual conditional headers and 304, changed 200, unsolicited/wrong-validator/late replies, tampering, scope isolation, accounted fetches, original dates/expiry and the collecting checkpoint. Ruff, format and checked-body MyPy passed. No external website or source credentials were used.

SKR-041 remains **implemented_pending_verification** for authenticated-source policy/integration and user-deferred hosted access-control/private-S3 acceptance; HTTP304 is no longer an implementation blocker.

## 2026-10-18 core launch hardening

Private replay now requires the connection's initiating owner and binds the stored
cache metadata to its opaque credential generation. Rotation makes old bodies and
conditional validators miss, including legacy private entries without a generation.
Generation and owner are rechecked before write persistence and after copied replay;
rotation during serialization cannot persist a stale response and rotation during
replay cannot return it. No credentials are decrypted or copied into metadata.
Public-cache behavior and original collection/publication dates are unchanged.

Fifteen targeted real-database cache/conditional-collection checks pass, including
rotation during read/write staging, cross-member denial and fresh post-rotation
repopulation. Ruff, formatting and checked-body MyPy pass. Production authenticated
source workers continue fresh reads rather than enabling replay implicitly. Enabling
that optimization in those workers and hosted private storage acceptance remain open;
the launch fix does not assert that those external/integration gates are complete.
