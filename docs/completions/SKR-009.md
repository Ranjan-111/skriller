## Runtime/access constraints

The acquired backend uses Patchright Chromium, an authenticated session, owned
profile directories and serialized browser operations. It includes automatic
browser-session import and login behaviour by default; our probe neither launches
the server nor imports credentials, and requires an operator-confirmed existing
session with automatic import/login disabled. Hosted deployments require isolated
tenant profiles, session-expiry handling and separate browser setup. Having
mcporter configuration alone proves none of these operations.

Current backend metadata requires Python >=3.12.4 and its own newer dependency
stack (FastMCP 4, MCP 2, httpx2, Patchright). It was deliberately **not installed
into the shared product environment or lockfile**. A separately locked worker
environment must be resolved and tested before runtime adoption; compatibility
with the product's installed MCP SDK client remains unvalidated live.

Open-source code licensing does not establish permission or commercial access
to LinkedIn data. Platform access, customer account/session suitability, result
coverage, quota/rate-limit behaviour and permitted deployment conditions remain
release decisions. No unrestricted-search or bot-bypass success is claimed.

## Probe and verification

`scripts/probes/linkedin.py` uses the installed MCP SDK to call only reviewed
read tools on an explicit loopback endpoint. It caps post search to one page,
profile reading to one scroll and the operation to 60 seconds. Reports expose
field/section names, reference count, section failures and elapsed time without
printing raw profile/session content. Partial and empty extraction do not count
as verified coverage; backend exceptions cannot print credential payloads.

- Offline CLI report: `status=skipped`, `validated=false`, `elapsed_ms=0`.
- Configuration-only report: `status=unvalidated`, never verified.
- Added probe tests: **7 passed, 1 live test skipped**.
- Ruff check/format passed for both probe scripts and their tests.
- Live test is opt-in via `SKRILLER_LIVE_TESTS=1` plus explicit endpoint/session
  confirmation/auto-import-disabled settings; absent credentials cause skip.

Example controlled invocation after a separately managed existing session/server
is ready:

```sh
.venv/bin/python scripts/probes/linkedin.py --live \
  --endpoint http://127.0.0.1:8000/mcp \
  --session-confirmed --auto-import-disabled \
  --operation search_posts --arguments '{"keywords":"fintech founder"}'
```

These flags are operator assertions, not proof of server configuration. Review
the server settings before opting in. A future successful report validates only
the requested operation/account/commit at that moment; it does not certify all
LinkedIn operations or production-scale reliability.
