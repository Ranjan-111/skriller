# SKR-083 bounded owner analytics reports

Status: **implemented_pending_verification**. The bounded backend adapter, copied-node summary helper, literal report UI, and private summary-job controls are implemented and locally tested. Real owner-report/browser acceptance remains open.

Added an authenticated owner-only report endpoint with a maximum 31-day historical interval. It supports daily `views`, `estimatedMinutesWatched`, and `averageViewDuration`; the channel is fixed by the owner's grant, never accepted from the request. Access-token expiry triggers one refresh before the report. Every result is fenced against grant revocation, expiration or generation changes after provider I/O. No new public scraping engine or private-to-public research fallback was added.

Exact returned numeric values, day labels, units, Pacific timezone, credential-free query provenance, collection time and canonical response hash are preserved. Missing days are not filled with zeros and coverage is explicitly incomplete. Unsupported metrics remain unavailable; empty, malformed, quota-limited or denied reports produce no guessed analytics. Revenue is unsupported and currency is null. Authentication rejection locally revokes the grant; quota failure does not. There are no automatic report retries or schedules.

The optional internal summary helper reuses the existing copied ScrapeGraph answer node, product model ledger, `ReportSelection`, `ResearchReport`, and `ReportObservation`. It selects complete literal metric lines rather than inventing trends. It requires an active job created by the same owner and rechecks the grant and job after model I/O. Default transport is explicitly local Ollama. Private metrics and model output are not written into workspace-shared evidence or research claims. Summary citation IDs are response-hash-bound identifiers, explicitly not saved evidence IDs.

Related public YouTube/retention/connections/schema checks passed **18 tests**, one opt-in live source test skipped. Ruff, MyPy, generated API/client contracts and TypeScript checks passed. No actual source or model request occurred.

## 2026-10-17 Sol: private summary persistence and one-shot execution

Added `analytics/private_jobs.py` and migrations 0046–0047. Trusted server-read
reports are bound once to an owner-created executable accounting job. Report and
summary contents are encrypted with the existing versioned AES-256 keyring;
AAD binds workspace, initiating owner, job, grant generation, state and expiry.
PostgreSQL RLS denies even another owner of the same workspace. Snapshots expire
within one hour or earlier grant expiry. Grant invalidation/refresh generation
changes wipe snapshots through a database trigger, including restore-time grant
revocation. Owner retention cleanup wipes expired snapshots across owners.

Execution commits a one-shot running marker before using the existing
`summarize_report` copied-node/ledger helper. Duplicate execution cannot repeat a
model call; uncertain running work is not automatically retried. Cancellation
wipes the payload and discards an in-flight answer. Results remain encrypted in
the initiating-owner table; no private metrics or answers enter shared evidence,
claims, job payloads or events. Ollama remains the default.

Verification: 30 PostgreSQL tests passed across private jobs, OAuth, analytics
reports and retention (7 new private-store/execution cases). Cases include
co-owner denial, encryption, wrong key/expiry tamper rejection, immutable snapshot
binding, single actual copied-node/ledger charge, cancellation and revocation
during model I/O, and expiry cleanup by another owner. Ruff and MyPy pass.
Controlled model/provider fixtures only; no external request or API key used.

This is backend progress, not completed user-facing dispatch: dedicated summary
job admission, authenticated submission/status/cancel routes, worker integration
and their API tests remain open, together with the previously recorded live
Google/browser gates. No summary button was enabled and the ticket is not done.


## Sol follow-through: authenticated admission/API and worker dispatch

Migration0048 adds the dedicated `owner_summary` purpose and routes it to the
existing reporting-stage scheduler and ID-only outbox. New `analytics/jobs.py`
adapts follow-up admission/checkpoint structure: one owner-created job, one model
call, 4096 tokens, 120-second original deadline, no source discovery/fetch budget.
Caller idempotency text is hashed before shared persistence. Report request and
answer remain only in encrypted private storage; shared conversation/plan/event/
broker records contain no private dates, channel, metric rows or response.
Disabled/exhausted workspace checks happen before report-provider I/O and again
at atomic admission. Duplicate submissions preserve the job/report and do not
read the provider again. Changed request intent rejects reuse.

Owner-only routes under the analytics prefix: POST `/summary-jobs` accepts
`grant_id` plus `report` (the existing ReportRequest) and required Idempotency-Key;
GET `/summary-jobs/{job_id}` returns private status/result; POST
`/summary-jobs/{job_id}/cancel` cancels shared accounting and wipes private work.
All responses are private/no-store. Another workspace owner cannot read/cancel
through these private routes. The research worker now dispatches the dedicated
reporting operation; leases/checkpoints and one-shot private claims prevent
uncertain model-call replay. Interrupted/expired leases fail closed with an
opaque reason; private results are discarded on interruption.

Verification: grouped analytics/CRM/OAuth/retention/actual-backup suite passed 87
cases; final added summary quota guard passed its 5-case API suite. Separate
shared-worker/entitlement/resume/follow-up regressions passed 44 cases, one existing
opt-in test skipped. Ruff/MyPy and actual generated OpenAPI/TypeScript checks pass.
No external model/provider, browser session, service restart or charge was used.

## 2026-10-17 Luna: private summary controls

The owner analytics screen submits a summary job for its selected grant and exact
date/metric report. It sends a stable idempotency key for retries of the same
request, polls with a two-minute bound, supports status refresh and cancellation,
and clears private values on account/workspace/grant/date/report changes. Returned
observations display only the service-provided quote and HTTPS provenance; unknowns
stay explicit, and the result is labelled private to owner analytics. The UI does
not persist report or model output to browser storage or shared research.
