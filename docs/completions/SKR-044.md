# SKR-044 — Evidence-preserving cleanup and copied chunking

**Component implemented and locally verified; fetch-stage integration awaits SKR-036.**

`src/skriller/extraction/cleanup.py` directly calls the copied ScrapeGraph
`cleanup_html`, `convert_to_md`, `split_text_into_chunks` and
`num_tokens_calculus` helpers. It reuses copied Scrapling Selector text extraction
and full XPath generation to retain evidence before pruning. No new token/chunk
or relocation algorithm was written; reduction level 2 is never invoked.
The copied cleanup's actual five-item tuple is validated rather than treating
its inaccurate `str` annotation as the runtime contract.

Head/body JSON-LD raw text, parsed values, original DOM locators and complete
name/role quotes are captured first. Malformed JSON-LD remains untrusted evidence
with an explicit issue. Executable scripts and styles are removed before cleanup;
non-JSONLD scripts are counted as excluded rather than claimed analysed. Missing
body fragments/head-only content are repaired with a visible issue so the copied
helper can operate. Long evidence is not silently truncated to 20 characters.

Input bytes, source URL metadata, evidence nodes/characters, chunk token estimates
and chunk count are bounded. Excluded evidence/chunks and oversized copied chunks
are visible. Evidence quotes are kept separately for validation and are not
secretly appended beyond bounded model chunks. Coverage is explicitly scoped to
`body_text_title_jsonld`; preparation is not model analysis. Source identity uses
the original-content SHA256 and original source URL/DOM XPath.

`PreparedContext.model_payload()` returns a data-only `untrusted_source` envelope.
Page instructions and JSON-LD keys named system/tool remain source data and never
become adapter configuration, model policy or executable commands. This component
runs no source fetch, script, shell or model request. Actual model prompt-injection
resistance and secret isolation remain SKR-045/046/077 integration checks.
