2026-10-13 public HTTP active-cancellation investigation: this seam remains **blocked by the installed transport interface**. Installed `curl_cffi 0.16.3` exposes `CurlOpt.XFERINFOFUNCTION` (20219), but its public `Curl.setopt` conversion only registers specific write/header/read/debug/seek callbacks; the generic callback option path raises `NotImplementedError: Option unsupported: 20219`. A no-network probe reproduced that refusal with both a Python callable and an allocated CFFI callback. The installed FFI does not declare `curl_off_t` (`int64_t` is present and eight bytes), so accepting an assumed callback layout via the private `_curl_easy_setopt` entry point would require bypassing the supported SDK boundary. No private callback shim, copied-upstream rewrite or alternate transport was introduced.

The [official libcurl XFERINFOFUNCTION documentation](https://curl.se/libcurl/c/CURLOPT_XFERINFOFUNCTION.html) defines a callback taking a user pointer and four `curl_off_t` values; returning one aborts transfer, `NOPROGRESS=0` enables it, and idle transfers may invoke it about once per second. The [official curl_cffi public setopt implementation](https://curl-cffi.readthedocs.io/en/latest/_modules/curl_cffi/curl.html) corroborates the unsupported generic callback conversion found locally. Therefore the required actual copied `FetcherSession` slow-header cancellation within five seconds is **not implemented or verified**; existing request deadlines and post-request artifact-write fencing remain the current boundary.
