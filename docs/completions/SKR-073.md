# SKR-073 — encrypted local restore rehearsal

Implemented a bounded operator utility that uses PostgreSQL exported snapshots for a consistent custom-format database dump and corresponding integrity-checked local private blobs. It reuses copied Agent-Reach private path/read/write helpers and the existing versioned AES-256-GCM keyring. Archives have authenticated encryption, private permissions, a seven-day default expiry and a thirty-day maximum. Authenticated expired .enc archives can be physically pruned; archives/keys are never committed.

Restore refuses the source database, non-loopback connections, nonempty target databases and existing object directories. It accepts only explicitly named skriller_restore_* rehearsal targets, applies current migrations, imports the latest deletion journal, uses restricted tenant sessions to cancel restored active jobs and replay erasures, then verifies surviving evidence digests. It never attaches the target to a service or enables traffic. A current independently encrypted deletion receipt supports source-database loss; its currency must be asserted by the recovery operator. Without a receipt, source access is mandatory and fails closed.

Verification: actual pg_dump/pg_restore into a clean isolated PostgreSQL database, two tenants, claims/private evidence, one queued job, backup-before-deletion and source-database destruction. Erased claims/blob stay absent, retained evidence is intact, the queued job is cancelled and tenant membership is enforced. Wrong key, corrupted ciphertext and expired archive rejection, physical expiry cleanup and nonempty-target rejection also pass. Measured fixture snapshot age and restore duration are in LOCAL-BACKUP-RESTORE.json; these are a small-fixture rehearsal, not a production RPO/RTO assertion. Ruff/MyPy pass.

Remaining before done: deploy and verify daily or more frequent encrypted off-host backup custody, independent latest-journal custody and expiry/key recovery; rehearse the actual pilot volume and record measured <=24h RPO / <=4h RTO. Local development test databases contain synthetic blobs in separate temporary fixture stores, so the utility correctly refuses a full development backup whose evidence pointers cannot be resolved from the configured object store. No production backup or recovery claim is made.
