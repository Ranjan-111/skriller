# SKR-062 — Reddit post/comment reads and quoted problem signals

## Local backend implemented — 2026-10-17

Copied the pinned rdt-cli `get_post_comments` method with its AST unchanged into
the existing transport-free vendor seam; provenance records both source and
target hashes. The unchanged acquired post-detail/comment parser supplies the
resource model. Product guards bound the raw response, total nodes, nesting,
resource IDs, parent relationships, post/community identity, text and dates.
Deleted/removed bodies stay unavailable. More-comment nodes and omitted replies
remain explicit; no expansion or hidden extra requests occur. Unknown source
comment counts cannot certify complete coverage.

The reviewed `reddit_oauth_read` operation uses the existing isolated worker,
fixed OAuth host, GET-only transport, no redirects/retries, private credential
delivery and initiating-owner/read-scope authority checks. Search results record
private connection/generation bindings for later collection. A collecting attempt
requires that exact binding before I/O and before persistence; old checkpoints,
replacement credentials, cancellation, expiry and kill switches cannot silently
select another account. The durable stage uses shared HTTP capacity and the
existing fetch budget/deadline/checkpoint controls.

Private thread evidence retains post/comment boundaries, source dates and links.
Content-free comment indexes connect nested-comment erasure to the shared evidence
blob, including restore replay. Evidence expiration or erasure removes the thread
from result output. Private connection/generation IDs are excluded from the API.

An optional saved-evidence extraction stage reuses the copied ScrapeGraph answer
node, existing model ledger and configured local model path. It makes at most one
bounded chunk call per thread and accepts only exact problem quotes from the
identified resource. Cross-resource quotes, fabricated IDs and fabricated text
are rejected. Dates/links come from the read result. Signals stay
`source_specific_unverified`; buying intent is `not_inferred`, subject identity is
unknown, and no company/email/contact claim is created. API validation independently
checks each signal against its retained source resource.

## Local results UI and verification — 2026-10-17

The generated `reddit_thread` response is now validated at the web API boundary.
It is accepted only on native Reddit public-post candidates, with bounded Reddit
permalinks, IDs, parent order, dates, tombstone bodies, counts and exact
resource-bound signal quotes. Malformed parents, deleted text, cross-resource or
invented quotes, unsafe links, and provider/source mismatches are rejected.

The results view exposes a collapsed post/comment thread with source links,
published dates or an explicit unavailable-date label, deleted/removed markers,
and nested reply relationships. It reports omitted comments and unexpanded reply
groups, and labels extracted quotes source-specific and unverified. The view
continues to state unknown identity and that buying intent is not inferred. The
existing source CSV/JSON whitelist remains unchanged; regression tests confirm
the private retained thread body and signals do not enter those exports.
