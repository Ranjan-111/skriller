## Reviewed-founder backend checkpoint — 2026-10-17

A third scenario now creates the original immutable plan through the production
intent-grounding validator, then executes both actual native adapters, private
collection and the copied saved-content extraction graph. Controlled model responses
produce literal job-title/date drafts and a resource-grounded Reddit problem quote.
No fixture claim is inserted as accepted. The unreviewed founder initially fails
qualification and report admission.

This exposed two production gaps. Native subjects remain `other`, while role review
previously required `person`; preview/approval now support explicit owner confirmation
of that candidate's exact saved LinkedIn profile. Approval without the new confirmation
fails atomically. The second gap was the planner's `role` field versus reviewed
`job_title`/`current_role` evidence. That comparison now uses current reviewed titles
with unchanged evidence, conflict and chronology fences; bounded grammatical role
normalization preserves the request. Model guesses cannot silently resolve ambiguous
person/company geography, while explicit subsequent user clarification works.

After the actual owner-preview/approval API, the founder's current role qualifies,
the follow-up worker emits a cited saved-source statement, and refinement creates a
new immutable revision. Raw profile identity stays unknown. The Reddit problem quote
stays separate, with no named buyer, identity merge or inferred buying intent.

See [owner review runbook](../OWNER_ROLE_REVIEW_RUNBOOK.md). The final related
backend selection passed **138 checks, with 2 optional model tests skipped**;
111 web regressions, TypeScript, generated contracts, Ruff and five-module
checked-body MyPy passed. The optional actual Llama semantic diagnostic was run

The results panel now lets an owner choose existing role/date observations from the

person status when required. The strict client binds workspace, entity, claim/date/
evidence references and both returned source URLs to the selected profile. Owner
403s retain current results; evidence conflicts and unclear mutation responses
refresh/re-preview rather than replaying a potentially stale hash. Success refreshes
qualification results. No new claim text, source call, automatic approval, identity

The focused frontend API/results suites passed **114 tests**, TypeScript and
