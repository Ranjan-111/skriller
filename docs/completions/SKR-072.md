# SKR-072 — erasure, suppression and deletion replay

Owner-only DELETE /v1/workspaces/{workspace_id}/entities/{entity_id}, with an Idempotency-Key, erases known linked identities. It cancels active workspace research before fencing writes, removes their claims and identity/role history, deletes linked private blobs, clears evidence excerpts/digests/source URLs, and tombstones entity payloads. Workspace response caches, saved-list snapshots and private exports are invalidated because they can contain copied values. This deliberately broad derivative effect is part of the API's documented behavior. No user data was deleted during development; only synthetic fixtures were used.

The immutable tenant-scoped journal retains opaque entity IDs, workspace-specific SHA-256 canonical URL markers, actor, time and request key. Discovery, cache writes, collection and extraction consult suppression under the same privacy fence. Alternate known linked URLs stay suppressed; unrelated unknown URLs cannot be inferred to belong to the deleted person. Migrating to 0022 preserves explicit errors for ordinary protected-history deletion; owner erasure requires a matching journal context. Journal rows cannot be changed/deleted by the application role.

Verification: seven real PostgreSQL erasure cases cover owner/member/API/idempotency boundaries, another tenant, linked alternate URLs, in-flight collected results, new discovery/cache writes, normal history immutability and derivative invalidation. The encrypted restore rehearsal restores a backup predating deletion into a fresh isolated PostgreSQL database after destroying the source fixture database; an independently encrypted current journal removes restored claims/blob before the result can be served. The other tenant's evidence and membership restrictions remain intact. See LOCAL-BACKUP-RESTORE.json. Nine erasure/recovery cases passed in the final focused run; 72 retention/list/identity/contact/cache/export regressions passed before adding the last rediscovery case. Ruff/MyPy and generated API contract/type checks pass.

Status: done for the declared erasure/suppression/replay scope. Hosted backup scheduling/off-host custody are tracked in SKR-073/074. This does not close source-reader, identity-quality or qualification orchestration gates.

Additional privacy seam verification: export and list-refresh creation now acquire the same privacy fence before reading copied values; identity writers share it, and claim creation refuses tombstones. Known identity groups are reloaded after the fence. A real two-connection concurrent export/delete case pauses serialization in flight, demonstrates deletion waits, then confirms the committed export blob is invalidated and late claims are rejected.
