# SKR-017 — Durable jobs, attempts, events, outbox and usage

Implemented and verified against real project-local PostgreSQL 18.4. All three jobs integration tests and seven numeric tests pass; full persistence/storage suite: 26 passed.

Added canonical jobs referencing a same-workspace/conversation immutable plan, deduplicated logical attempts, append-only sequenced events and usage ledger, an ID-only transactional outbox, and exact-decimal budget reservations. All foreign references carry workspace ownership. Atomic PostgreSQL ON CONFLICT deduplication cannot silently reuse an idempotency key for a different operation. Events support ordered resumable cursors. Job state recovery reads PostgreSQL independently of Celery caches.

Job states match PRD: planned, queued, running, waiting_for_connection, paused, completed, partial, failed, cancelled. Stages remain separate. `JOB_TRANSITIONS` is a reusable pure map for downstream orchestration; repository updates lock rows and enforce this map. The root state-machine ticket may refine the map rather than duplicate transition logic. Attempts have pending/running/succeeded/failed/cancelled statuses.

Outbox payload construction returns only workspace/job/actor/optional attempt IDs. Actor is an opaque server-verified Firebase UID; no authentication token, browser session, prompt, or page body enters this payload. Actual broker publication is a downstream queue ticket; these persistence tests inspect the generated payload rather than claim broker delivery.

Three PostgreSQL tests are ready: two concurrent worker connections deduplicate one attempt/usage record, fresh connection recovers job/event/outbox state with terminal transition protection, and cross-tenant plan association fails. Seven offline numeric tests passed, rejecting nonfinite/negative/excess-precision/overflow amounts while preserving low-cost decimal precision. Ruff, migration SQL generation and compile checks pass. Real database attempts currently fail before schema execution because local PostgreSQL closes connections unexpectedly.

Recovery verification (2026-10-12): official checksum-verified PostgreSQL 18.4 was built and installed only under `.runtime/postgres`; its dedicated `.runtime/postgres-data` cluster runs on loopback port 54439. Concurrent attempt/usage deduplication, fresh-connection recovery, immutable events, and cross-tenant plan rejection all passed on the restricted application role. Original Docker volumes and settings were preserved. Prior failed attempts describe recovered infrastructure, not the final result.
