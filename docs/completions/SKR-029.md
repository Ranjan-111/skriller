## Installed credential delivery and execution controls — 2026-10-16

**SKR-029 is done for its declared encrypted-storage and allowlisted worker-loading scope.** `RunnerSecrets` now carries the opaque credential-row generation. `ConnectionStore.runner_current` validates that exact generation, workspace/actor, original plan, live job/deadline/budget, source read switch, active connection and expiry without decrypting again or generating repeated load audits. Reddit session cookies and OAuth tokens use different allowlisted fields; no cookie is inferred from a token.

`connections/execution.py` loads once and fences a trusted isolated runner before dispatch, during execution and after completion. Revoke, reconnect or expiry invalidates the old reference; late output is discarded. Cleanup failures remain visible with source output withheld. Executor/control exceptions are redacted. Source adapters retain their own accounting, capacity and final evidence authorization responsibilities.

The existing `IsolatedRunner` can deliver matching source material through a fresh 0600 JSON file in a 0700 directory, mounted read-only at a fixed worker path. Values enter neither argv nor container environment metadata. Credential-bearing containers use Docker's `none` log driver; returned stdout redacts known secrets and backend stderr is discarded. Temporary plaintext is removed on success, cancellation and launch exceptions. A credential cannot be passed to a public YouTube operation or an unknown runner field. Production command allowlisting is unchanged: LinkedIn/Reddit platform commands are not enabled by this transport work.

Two actual installed guarded-image cases passed with synthetic encrypted credentials: inspect verified no raw secret in container metadata and a read-only secret mount with logging disabled; successful output was redacted; persisted revocation stopped the running worker within five seconds; container/workspace/credential files were removed. No platform account or external source was contacted. Controlled PostgreSQL cases cover generation mismatch, zero attempts, reconnect/expiry/revoke, one-time load auditing, distinct Reddit auth kinds, late-output rejection and redacted executor exceptions.
