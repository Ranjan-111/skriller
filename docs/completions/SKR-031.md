# SKR-031 — Context-owned typed connector registry

Implementation and local contract/regression checks pass. This ticket establishes
routing and capability honesty; it does not establish live source readiness.

`src/skriller/connectors/registry.py` directly reuses the copied Agent-Reach
registry order, concrete Channel classes, `Channel.ordered_backends`, platform
`can_handle` methods and `normalize_public_http_url`. It creates fresh channel
instances with instance-owned backend lists and fresh active_backend state for
each workspace registry. Original singleton objects and class backend lists are
never mutated. Imported source files remain unchanged; their original provenance
and licenses remain in `third_party/agent-reach`.

The supported contract sources are LinkedIn, Reddit, GitHub, YouTube, RSS, X,
Instagram, Facebook and generic web. Upstream platform-specific channels retain
precedence before RSS and generic web. A missing/unverified dedicated operation
never falls silently into generic web. Known-source URL mismatches and unsafe
URL syntax are rejected before route selection. DNS/socket enforcement remains
SKR-027's proxy boundary, rather than being claimed by routing validation.

`ConnectorRegistry(workspace_id, backend_preferences=..., connected_sources=...)`
provides `channel`, `ordered_backends`, `capability`, `capabilities`, `select`,
`register_adapter`, and `record_verification`. `select` returns `RouteSelection`
or the product `Failure` contract. `AdapterBinding` is an application-only,
reviewed registration; callers do not supply code through a customer endpoint.
Bindings copy their mutable Capability input so later caller mutation cannot
change the registered route. Duplicate and planned executable registrations fail.

Every default source-operation row remains planned and unavailable or needing
connection. Upstream installation/diagnostic `check()` results are not used as
proof of discover/read functionality, and registry construction never reads home
credentials, runs CLI probes, or invokes platform requests. Even a registered
adapter claiming available is downgraded to experimental until a current trusted
`OperationVerification` exists for the same workspace, backend and operation.
Connection configuration alone cannot create availability. Expired, future,
failed, naive-timestamp and cross-workspace/backend verifications cannot do so.
Explicit rate-limited, unavailable and access-agreement states remain effective.
