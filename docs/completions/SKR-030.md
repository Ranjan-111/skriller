# SKR-030 — Connection lifecycle API

Authenticated metadata-only endpoints support create, reconnect, revoke and expiry purge. Reconnect invalidates old credentials atomically. Bounded request bodies and private validation errors prevent credential echo. Stored configuration is explicitly not remote access verification.

Verification: 6 real PostgreSQL API lifecycle tests plus 11 vault regressions passed.

Remaining: Live source authorization, remote revocation and active runner cancellation remain unverified.

Status: implemented_pending_verification.

## Local active-execution lifecycle — 2026-10-16

The vault-to-runner boundary now observes revocation, expiry and reconnection during execution and fences late output by exact credential generation. An actual installed guarded worker was cancelled and removed after persisted revocation using only a synthetic encrypted source connection. Reconnection creates a new opaque reference and invalidates the old worker; it never substitutes credentials into an already-running operation. Generation checks do not decrypt repeatedly or append repeated loaded audits. SKR-029 records the installed-file-delivery/security proof.

The former active runner cancellation gap is closed for this shared boundary. ## Explicit replacement selection and resume — 2026-10-17

Local `rebind-options` and `rebind-and-resume` endpoints now admit a fresh selected
LinkedIn/Reddit generation for undispatched collecting work. Only the initiating
workspace owner may inspect/select bindings, and the replacement must be owned by
that actor. Admission reuses current source/auth/scope, expiry, kill-switch,
entitlement and original job-deadline controls. Original source cursors, source
provenance and completed evidence are unchanged. All pending native candidates for
the source must be included. No original credential or generation is returned in
selection metadata. The current generation is privately persisted and checked again
at execution; reconnection never substitutes into an active process.
