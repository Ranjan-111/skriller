# SKR-032 — operation diagnostics and kill switches

Implemented product metadata diagnostics for all nine contract sources and discover/read/analytics operations, and authenticated workspace owner PUT kill switches. The independent channel aggregation and exception boundary are adapted from the supplied Agent-Reach `doctor.check_all`; product diagnostics discard all exception content and never invoke host account, browser, CLI, credential or network discovery.

Current Exa keyless discovery is explicitly experimental public indexed references, with title/URL/snippet fields. It does not imply direct authenticated LinkedIn/Reddit access, profile extraction or analytics. Globally disabled search reports unavailable. Stored credentials do not imply live verification. Reviewed registry operations retain their own current verification semantics. One failed diagnostic cannot hide unrelated operations.

Migration 0013 installs forced tenant RLS and owner-only switch mutations, including actor binding. Members can read metadata. Foreign actors cannot inspect it. Switches apply per source and operation; repeated changes are idempotent and do not delete evidence/results. The research dispatcher checks each discover switch immediately before provider IO; a disabled queued source produces a visible limitation while other sources continue. Re-enabling permits a new job and leaves the previous results unchanged.
