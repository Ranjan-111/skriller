# SKR-059 — LinkedIn discovery and reference routing

Implemented an explicit indexed LinkedIn reference contract in the actual job-results path. Routing calls the copied Agent-Reach `LinkedInChannel.can_handle`; resource identity reuses the existing native permalink discriminator. Profile/company/post paths receive bounded resource kinds, other paths remain unknown. Each reference explicitly reports `exa_keyless`, `indexed_reference_only`, `not_attempted` direct reading, and unknown subject identity. Source provenance, snippets, unverified qualification and original references remain intact. No account/session read or claim of full profile access is introduced.

Verification: 12 platform routing contracts cover LinkedIn/Reddit references and lookalike hosts. Real PostgreSQL job/result tests verify indexed post metadata without subject/author invention. Combined planner, discovery and follow-up run: 83 passed, 2 optional tests skipped; three broker/runtime cases were excluded from that selection and then separately verified (one actual RabbitMQ delivery, two runtime retry cases). Ruff, four-module MyPy, generated OpenAPI/client, TypeScript and contract drift checks pass. A transient combined-run broker handshake timeout did not recur in the isolated actual-broker check; native broker ping passes.

Results UI now shows the reference resource kind and states that it came from search indexing, the selected operation did not directly read LinkedIn, and identity remains unverified. API-client validation rejects any result metadata that claims direct access or verified identity. UI/API tests pass **127 tests** across 15 files; TypeScript, generated contract drift, Prettier and diff checks pass. Impeccable detector reported no findings.

Status remains **in_progress**. Selected account-backed discovery integration and live operation/coverage verification remain user-deferred; the existing Exa feasibility report does not certify direct LinkedIn search or readable profiles.

## Sol isolated native discovery and durable integration — 2026-10-17

Added the immutable LinkedIn worker image by copying the complete acquired backend
package and notices into the existing reviewed browser image. The worker reuses
its page session, navigation, content capture and permalink listener, selecting
the single-attempt capture primitive rather than the upstream rate-limit retry.
It accepts only typed people/post searches, an encrypted owner session delivered
through the existing private runner file, and bounded read requests. It never
imports host browser state or starts a login, MCP server or daemon. Browser
contexts are ephemeral. Source switches, current owner/creator, scope, deadline,
cancellation and credential generation are checked before and after execution.

The optional native route is integrated into durable discovery using browser
capacity and the job's existing search-call reservation/checkpoint ledger. Only
the initiating owner's session is eligible; ambiguous selections fail, replacement
does not rebind an old call, and a failed native attempt does not fall back to
indexing or retry later variants. Indexed discovery remains the default without
an eligible configured session. No actual source setting was enabled.

Search results preserve `linkedin_mcp` / `search_reference` provenance. Page text
remains unaligned and is not assigned to a person or post; only the reference's
own label is retained as its snippet. Platform metadata explicitly says connected
search reference, direct reading not attempted and identity unknown. Integration
tests found and fixed an existing parser mismatch: the acquired backend's relative
links now become absolute LinkedIn URLs, while external/protocol-relative links
remain rejected. API schemas and generated client types reflect this contract.

Verification: **146 distinct related backend/database/security tests passed, 1 live
test skipped** (129 grouped plus 17 request/metadata boundary checks);
**1 installed-container check passed**, exercising both people and post
search through the actual copied extractor with Docker networking disabled and
cleanup confirmed. The acquired snapshot hashes match their manifest. Eleven
source modules pass checked-body MyPy; Ruff and formatting pass. **104 existing
client/export/results regression tests**, TypeScript, generated-contract and actual
API-schema drift checks pass.

## Luna strict client integration — 2026-10-17

The runtime API client now accepts `linkedin_mcp` / `search_reference` only when
candidate and each provenance row identify LinkedIn. It accepts native metadata
only as `linkedin_mcp` / `connected_search_reference_only` with direct reads
unattempted and identity unknown. Indexed Exa references retain their separate
contract and must match the candidate's source. Mixed source, provider, evidence,
backend, access, direct-read and identity combinations are rejected.

Results identify native items as connected search references and explain that no
profile or post was opened. JSON and CSV exports retain platform metadata and the
provider/evidence/provenance values. Reddit and X connection panels now keep the
empty state and connect action unavailable until consent metadata finishes
loading, preventing an early click from racing the initial workspace lookup.

payloads, native results/exports, and both connection panels. TypeScript and
generated contract drift checks and Next production build pass. The Impeccable
detector reported no findings. Live account-backed and hosted acceptance remain deferred; the optional
native LinkedIn environment setting remains disabled. See
[runbook](../LINKEDIN_SEARCH_RUNBOOK.md) and [installed-worker evidence](LINKEDIN-WORKER-LOCAL.json).
