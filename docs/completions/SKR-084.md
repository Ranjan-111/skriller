## 2026-10-17 — PKCE lifecycle and installed worker

Implemented owner-consented PKCE S256 exchange and refresh using the existing
CRM transport/consent patterns. The main API exposes owner list/start/complete/
refresh/local-revoke routes. Migration 0053 stores only encrypted initiating-owner
consent material; token/code exchanges are committed as consumed before external
I/O, so crash/rotation uncertainty cannot replay an old credential. Successful
refresh creates a replacement source connection and retires the previous access
reference. The read runner receives only access material. Retention never extends
past 30 days, and actual access expiry is taken from the bounded native receipt.
Remote provider revocation and unattended renewal are not claimed.

Migration 0054 adds a boolean-only database fence that sees private consent state
across actor RLS boundaries. It blocks use during refresh, after consent expiry/
revocation and after the initiating owner's demotion. Co-owners cannot decrypt or
complete another owner's grant. Retention wipes both token envelopes, and actual
encrypted backup restore proves archived refresh grants are revoked and cleared.

Fixed a non-working image definition: the former Dockerfile omitted its runtime
dependency closure and inherited eager orchestration imports. The image now uses
the pinned guarded base, five hash-verified `uv.lock` wheels installed offline,
lazy connector exports, and the unchanged copied Scrapling Retry-After function
with standard-library imports. The source license ships in the image. No browser
is installed. The installed production module runs with synthetic credentials in
a network-none fixture; actual kernel, filesystem, private credential delivery,
redaction and cancellation/revocation checks pass. Image/probe evidence is in
`X-WORKER-LOCAL.json` and operation details in `docs/X_OAUTH_RUNBOOK.md`.

The full pinned-source check found two pre-existing whitespace edits in unused
reference CLI/output files. Compared both with the exact pinned GitHub commit:
their syntax trees match. Original upstream hashes remain; verified local
formatting hashes and a modification record preserve the existing files. The
