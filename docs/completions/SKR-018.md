# SKR-018 — Private evidence object storage

Implemented provisionally; not verified complete. SKR-016 and both real PostgreSQL storage integration tests now pass on the recovered project-local native PostgreSQL 18.4 cluster. Live S3 deployment verification remains outstanding. No SQLite or mocked repository substitutes are used.

Added typed `BlobBackend` and S3 client protocols, `LocalBlobBackend`, `S3BlobBackend`, and `EvidenceStorage`. Backend-neutral keys are `<workspace UUID>/evidence/<random UUID hex>` and reject other workspace keys/path traversal. The local backend creates private directories/files, uses descriptor-relative directory traversal and `O_NOFOLLOW`, rejects symlink escapes, and refuses overwrites. S3 construction fails closed unless public access blocking is enabled and no group ACL grants exist. Writes require server-side AES256 encryption and conditional no-overwrite; retrieval returns bytes through application authorization rather than public/presigned URLs. Unsupported privacy-check APIs fail closed.

`EvidenceStorage.store` uses an existing tenant database session and ResearchRepository.add_evidence, records SHA256 and expiry metadata, checks size/expiration before writing, and removes a blob if repository insertion immediately fails. `retrieve` looks up an evidence ID through ResearchRepository.get_evidence before accessing storage, rejects missing/expired records, bounds byte reads, validates tenant key ownership, and verifies the digest. Typed errors distinguish unavailable, oversized, and corrupt content. Stable keys survive backend migration when bytes are migrated under the same key.

Verification actually run: **5 tests passed** against actual local filesystem plus an explicitly identified S3 wire-contract double and boto3/botocore SDK Stubber request validation (no network). Tests cover private file mode, roundtrip/deletion, wrong workspace, size bound, immutable writes, path traversal/symlink escape, privacy flag/ACL rejection, S3 encryption/conditional-write arguments and bounded stream closure, prewrite expiration/size rejection, and typed missing-object handling through the actual S3 SDK validation layer. Ruff and mypy pass for storage/core source. Both genuine PostgreSQL integration tests passed, covering cross-workspace evidence retrieval, expired records, integrity, oversized writes, and migration preserving evidence references. The combined persistence/storage suite passed all 26 tests using owner migrations and restricted application-role queries on port 54439. Live S3 service verification has not run; a wire-contract double does not establish deployment bucket configuration or provider compatibility.

Operational limits: S3 client must be created with bounded network retries/timeouts by the deployment factory; this library accepts an injected configured client. Server-side bucket privacy must remain enforced after startup. Failed outer database commits can leave unreferenced private blobs; retention/orphan cleanup belongs to SKR-071. Blob writes cannot participate atomically in a PostgreSQL transaction; no uncommitted database reference is served through this interface.

## Sol runtime selection and storage hardening — 2026-10-15

API lifespan, collector, saved-page extractor and retention now share `configured_storage(Settings)`. Local remains default; explicit S3 uses bounded SDK connect/read timeouts, one total attempt (no retries), workload-role or complete secret credentials, mandatory bucket privacy checks and owner-only canonical ACL grants. Settings errors hide input values; credentials never enter representations. HTTP endpoints are allowed only on local development loopback, otherwise HTTPS is required. Created SDK clients close on failed initialization and owned service/job completion. Local backup/rehearsal refuses S3 instead of silently archiving the unrelated local directory.

Local retrieval now opens nonblocking and rejects nonregular files before reading, including FIFO and directory inputs. Invalid timezone-less expirations retain the typed storage error. Tests verify FIFO refusal with a child-process timeout, external canonical/email ACL denial, bounded real SDK setup/lifecycle, redacted failures, configuration rejection, and local-to-S3 reference migration against real PostgreSQL plus the official SDK Stubber. This last test is a request-contract proof, not a live remote service.
