# SKR-063 — Public GitHub metadata adapter

Added a bounded async GitHub public API reader for repository metadata and explicitly published user/organization profile fields. It returns typed, dated evidence with `public_only` access scope and keeps public counters identified as API metadata. It makes unauthenticated GET requests only to the exact repository and profile routes, with fixed `api.github.com` origin, short timeout, redirect refusal, a 256 KB response cap, and typed unavailable/rate-limit outcomes. It has no token/`gh` credential path and no issue, pull-request, clone, or private-resource operation.

The copied Agent-Reach GitHub channel was inspected: its only backend is a local `gh` CLI readiness check, not a public-data reader. This adapter reuses Agent-Reach's copied URL normalizer/domain guard for input URLs; the public REST integration is new product glue because the supplied channel has no compatible read implementation. The API deliberately returns the same `not_found` state for missing and inaccessible private repositories, matching GitHub's public API behavior and avoiding a claim that private access was checked.

Verification: **8 async connector tests passed**, followed by a two-request live read of the public octocat/Hello-World repository and public octocat profile; both returned public-only dated records. No credential or private resource was used. The tests cover typed dated public evidence, omission of unrequested email fields, no Authorization header, exact GET allowlist, inaccessible-resource behavior, fixed public URL validation, rate-limit classification, redirect refusal and bounded response size. Ruff and MyPy pass.

Ticket remains `implemented_pending_verification`: production collection routing, workspace persistence, shared-budget accounting and evidence qualification depend on the larger connector/job pipeline. The adapter alone is not presented as an end-to-end research connector.

## Sol public collecting integration — 2026-10-14

A discovery-owned GitHub candidate now routes to the existing public reader through a durable collecting attempt, the configured GuardedProxy and the shared HTTP/source/host capacity and budget ledger. There is one bounded API call, no credentials, redirect, retry, clone, issue or PR operation. Cancellation/deadline/owner kill-switch checks surround live IO; a cancelled or erased result cannot persist. Typed failures retain indexed references without fabricating source facts. Copied Scrapling Retry-After parsing feeds shared cadence on rate limits. API resource fields persist as private integrity-checked evidence with a thirty-day ceiling; no model call is made. JSON metadata is not sent to the page-extraction graph.

Repository and profile native IDs are retained with distinct namespaces. Repository ID/stars/forks and profile ID/followers/public-repository counts are source-specific accepted observations over the exact validated API resource, not accepted business identity or lead fit. Arbitrary owner fields and profile email are excluded. Response URLs must match the requested subject; numeric IDs/counters have strict types. A repository cannot qualify as a company/person lead, and an account's Organization/User type does not automatically establish the requested business/person identity. Lead qualification remains unverified in result views. All private attribute names are omitted from the API. Source diagnostics register this actual public adapter as implemented/experimental; they do not assert permanent availability or private access.
