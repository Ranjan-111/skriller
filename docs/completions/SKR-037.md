# SKR-037 — source-aware classification implemented and fixture verified

`src/skriller/connectors/classification.py` directly reuses the copied Agent-Reach `_is_antibot_page` routine and copied Scrapling `StealthySessionMixin._detect_cloudflare` static detector. It invokes neither channel network readers nor browser/session constructors nor challenge solvers. New product glue adds source-specific login/checkpoint route recognition, password/login gates, visible DOM context, explicit empty-result states and unrendered application shell detection around those existing detectors.

The typed PageClassification separates readable content, challenge, authentication required, access denied, rate-limited, JS shell, genuine empty results, empty body, unsupported content and HTTP unavailability. It records next_method extract/dynamic/connection/stop and evidence_kind page_read/empty_results/none. These are routing decisions only: no fallback, browser, login, solver or retry is automatically dispatched. Login/challenge/JS-shell bodies yield no accepted read artifact or lead fields. A captured generic page never becomes profile_read merely because its URL belongs to LinkedIn or another platform.

The copied HTTP adapter now classifies successful responses before returning an artifact for persistence/extraction. FetchUnavailable exposes the typed classification for applicable method selection. Genuine explicit empty-result pages can be stored as empty_results evidence with next_method stop; this is not a result containing lead fields. Metadata persistence includes classification and next_method. Artifact persistence independently rejects a blocked classification. Existing deadline, capacity, attempt, proxy and replay accounting boundaries are unchanged.

Context checks prevent an embedded Turnstile on a readable company/contact form from being mistaken for a challenge wall, prevent security articles that mention login from being mistaken for authentication gates, and prevent hidden empty markers or an empty sidebar from overriding visible result content. Unknown/ambiguous platform structures still require connector verification; this fixture classifier is not an assurance that every live login/block page is recognizable. Empty-result and short login phrases are currently a bounded English vocabulary plus DOM/status/route guards, not a claim of universal locale coverage.
