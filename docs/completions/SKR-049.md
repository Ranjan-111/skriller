# SKR-049 — Reviewed reversible identity groups

Added `qualification/identity.py` and migration `0014_identity_reviews.py` (after 0013). This is new product logic because the supplied repositories contain no SaaS identity resolver.

Identity comparison uses tenant-owned accepted, observed claims with linked unexpired evidence. Same names never establish identity. Exact case-sensitive platform-native IDs can establish a reviewable match; conflicting native IDs keep a suggestion. Company domains require matching legal name and country as corroboration. Domain normalization reuses the copied AgentReach public URL guard. Person employer domains do not establish person identity. Unverified, conflicted or expired facts cannot authorize a link.

All proposed matches remain suggestions until an owner explicitly reviews them. Approval recomputes current facts and checks existing groups for contradictory identities; workspace advisory locking serializes link changes. Tenant RLS and owner write policies independently protect review rows. Append-only event rows record suggestion, approval and reversal. Group traversal and claim projection have explicit bounds.

Links form reversible read projections. Original entities and claim entity IDs are never rewritten, so reversal removes a particular reviewed edge while preserving all original claims and both histories. Other independently approved edges remain in effect. There is currently no list table or list integration; future list consumers must preserve original entity references and resolve groups at read time.

Validation: nine real PostgreSQL tests passed for same-name people at different firms, native ID conflicts and case sensitivity, unverified/expired evidence, domain corroboration, explicit review, changed facts before approval, reversible claim association, immutable audit rows, cross-workspace denial, member permission denial and transitive group conflicts. Ruff and MyPy with `--check-untyped-defs` pass.

Remaining gates: production candidate/evidence pipeline callers, source-specific stable native-ID semantics, list trace integration, owner review UI/API and deployment/quality corpus. This component is not a declaration that SKR-049 is fully complete.
