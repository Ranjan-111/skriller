# SKR-060 — bounded LinkedIn resource reads

## Local backend implemented — 2026-10-17

Typed profile, company-about and activity/UGC-post reads reuse the pinned acquired
LinkedIn `SectionCapture._capture_once`, `PageNavigator`, `PageSession` and
`PageContentReader` from the existing isolated image. No replacement DOM scraper,
contact overlay, ambient browser profile, account import, session renewal or
source retry was introduced. Explicit canonical resource URLs, one navigation,
80-request ceiling, GET/HEAD-only network routing and the existing guarded
browser sandbox bound the operation. Acquired source and notices are unchanged.

The separate `linkedin_resource_read` runner accepts only its private session
credential file. Current initiating owner/connection creator, session auth,
read scope, source switches, job state/revision, original deadline, cancellation
and credential generation are checked before and after execution. Discovery
persists private connection/generation bindings; later reads require those exact
values. Missing/ambiguous/older bindings require a fresh run. Read permission does
not require discovery permission; another member or co-owner cannot open the
initiating owner's session. Replaced credentials do not rebind old reads.

Authentication, account restriction, rate-limit and missing-page outcomes are
mapped from the acquired exception types to fixed safe codes. Challenge, redirect,
empty, failed and mismatched sections cannot produce resource evidence. Raw SDK
messages, cookies and provider diagnostic text are excluded from returned errors.

A durable collecting attempt reserves one fetch and uses shared browser capacity.
The bounded resource section is stored as private evidence, with escaped source
lines preserving quote boundaries. Expiry removes it from results; erasure removes
the entity/evidence, and checkpoint replay makes no additional source call. Existing
source-specific extraction reuses the copied saved-content graph and shared model
ledger with restricted profile/company/post presets. Private contacts are excluded;
source observations remain unverified, subject identity unknown, buying intent
not inferred and whole-resource coverage incomplete. An invented email fixture is
rejected while the exact supported job-title observation is retained.

Generated API contracts expose optional `linkedin_read: {evidence_id, resource}`.
The web client strictly validates resource UUID, candidate/provider/source pairing,
canonical LinkedIn URL binding, resource-kind/section pairing, bounded text,
timestamp and privacy constants. Results render the section as escaped literal
text with its source link, collection time, truncation notice and partial coverage
limits. Expired evidence keeps its historical read status and displays that the
retained text is unavailable. The existing CSV/JSON whitelist remains unchanged.
Successful resource reads suppress the old discovery-only “not attempted” notice;
original search provenance and search_reference evidence kind remain intact.
Actual native LinkedIn settings remain disabled.
