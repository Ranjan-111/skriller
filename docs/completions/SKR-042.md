# SKR-042 — Scoped adaptive fingerprint storage

**Implemented and verified against real restricted-role PostgreSQL.**

`src/skriller/adaptive/storage.py` directly inherits copied Scrapling
`StorageSystemMixin` and reuses `_get_base_url` plus the exact copied
`_StorageTools.element_to_dict` fingerprint algorithm used by its SQLite
storage. Relocation and similarity algorithms remain the original copied parser
implementation. No upstream/reference files were patched.

The PostgreSQL transport uses atomic upsert scoped by workspace, source, access,
domain, template UUID, template version and selector identifier. The persistence
agent supplied the scoped `adaptive_fingerprints` table, migration 0006 and FORCE
RLS tenant policy. A generated bounded selector hash prevents PostgreSQL btree
size failures for large identifiers. The unique constraint is `adaptive_namespace`;
upsert requires equality of the original identifier and reports a collision
instead of overwriting another key. Retrieval always matches the full identifier.
An older template version is neither deleted nor overwritten by a newer version.

The cached constructor has Scrapling's required `__wrapped__` mixin contract;
all cache arguments are immutable scope/context values plus Database identity.
Every operation opens an independent `Database.tenant` restricted-role,
membership-checked transaction; no mutable SQLAlchemy Session or cursor is cached.
Shared Database lifecycle remains the owner's responsibility.

`StorageScope` validates UUIDs, supported sources, positive integer versions and
canonical public/connection access namespaces. `storage_arguments` binds scope
and exact public/connection identity to trusted ExecutionContext, rejecting
cross-workspace or connection mismatches (including relabelling an authenticated
context public). Actor identity and public URL syntax are validated. Unknown
public suffixes preserve their hostname instead of sharing the upstream generic
'default' domain key. Selector IDs are bounded. Fingerprints are database records,
not arbitrary user-selected filesystem paths.

## Verification

The complete run used native PostgreSQL on loopback port 54439 through
`SKRILLER_DATABASE_URL` and `SKRILLER_APPLICATION_DATABASE_URL`, with the existing
real PostgreSQL fixture, owner migration setup and restricted application role.

- `.venv/bin/pytest tests/adaptive third_party/scrapling/tests/core/test_storage_core.py -q`:
  **39 passed** (15 product tests, including four real PostgreSQL tests; 24 copied
  upstream storage tests).
- `.venv/bin/mypy src/skriller/adaptive`: no issues in two source files.
- Ruff check/format: pass.
- Scrapling provenance verification: pass, imported source/reference unchanged.

Real PostgreSQL checks verify copied parser relocation with the new cached
constructor, original JSON fingerprint round-trip, identical domain/selector
isolation across every namespace key, unauthorized actor rejection, raw SQL RLS
blocking another workspace even when bypassing adapter predicates, preserved
rollback versions, concurrent independent transactions and a 4096-character
Unicode selector identifier with atomic updates. The explicit unit collision
failure regression confirms a rejected conflict is not reported as success.

Five warnings remain visible: two lxml HTMLParser deprecations and three copied
SQLite destructor double-close warnings. None were suppressed. The product
PostgreSQL adapter does not use the SQLite destructor or retain a connection.

This ticket verifies storage and parser interoperability. Semantic relocation
validation/quarantine belongs to SKR-043; live source fetching and browser egress
remain their separate gates. It does not imply any real platform is live-ready.
