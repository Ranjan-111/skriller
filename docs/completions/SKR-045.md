# SKR-045 — bounded local model adapter (provisional)

Implemented `src/skriller/extraction/models.py` with official ChatOllama and the copied `scrapegraphai.utils.output_parser.get_pydantic_output_parser`. Real ChatOllama calls bind the caller's JSON Schema per invocation, mirroring copied GenerateAnswerNode without mutating the shared model. The copied parser performs JSON parsing; explicit Pydantic validation enforces the caller's schema. Product code adds accounting, scoped authorization and limits rather than a replacement extraction engine.

Only `llama3.2:3b` and `deepseek-r1:8b` at fixed loopback Ollama are configured. Each invocation reserves one call and a conservative token bound before IO. Shared PostgreSQL model capacity limits concurrent calls, and persisted job, execution context and monotonic lease deadlines bound IO. Output prediction and context lengths are explicit. No retry or cloud fallback is configured. Tracing is disabled and errors omit prompts/provider details.

Known provider token metadata reconciles actual usage, including schema-invalid responses. Missing metadata, cancellation after invocation, and timeouts retain estimated bounds. Cancellation while a DB reservation thread commits waits for that thread and releases unused capacity/reservations. Actual token overruns are recorded and pause the job. A trusted copied-graph integration flag avoids duplicating schema instructions.

Verification: `pytest -q tests/db/test_models.py`: **24 passed**, real PostgreSQL with restricted application role and stub models. Ruff check and mypy for the adapter passed. Tests cover valid/null output, invalid schemas, unknown usage, cancellation, timeout, duplicate operations, budget exhaustion, shared capacity across jobs, persisted deadlines, allowlisted configuration, redaction and output overruns.

Controlled official SDK transport tests also verify JSON-schema format reaches the actual `/api/chat` request, output caps remain set, the shared client is not mutated, and a provider failure causes one request without fallback.

A bounded live planner trial using this new adapter first failed schema validation (9.484 seconds, 915 actual tokens); after the material per-call schema-format fix, one fresh trial passed schema validation but failed prompt-grounding checks (5.174 seconds, 941 actual tokens). Each trial made one call with no retry and zero currency cost. Evidence is in `PLANNER-LIVE-baseline.json` and `PLANNER-LIVE.json`. This does not establish factual extraction or planner semantic accuracy.

Remaining: production extraction/planning wiring and prerequisites, production container controls, and representative live quality evaluation. Earlier SmartScraperGraph trials do not verify this adapter. Do not mark the full ticket done from the current checks.
