# SKR-020 — Canonical job state machine

Implemented and verified on real native PostgreSQL 18.4 (port54439). This ticket reuses the existing `JOB_TRANSITIONS` map rather than adding a second state table. The lifecycle service is `skriller.jobs`; repository mutations remain canonical.

Added validated stage and terminal-reason semantics, immutable terminal outcomes, preserved stages on transitions, atomic versioned `state_changed` events, and optimistic expected-version checks under PostgreSQL row locking. Updating a stage while running increments the same job version; identical repeated transitions do not emit duplicate events. Terminal outcomes cannot restart or change their stage/reason/timestamp/version, including through direct database UPDATE; a new logical run needs a new job/idempotency key.

Migration0005 adds terminal_reason plus consistency/required constraints and terminal mutation protection. Completed means `source_exhausted` or `target_met`; partial means `budget_limit`, `deadline_limit`, or `source_interrupted` with saved results; those interruptions without saved results fail. Failed processing uses `processing_error`; cancellation uses `user_cancelled`. Source exhaustion may legitimately complete with zero matches. `finish` receives a checkpointed result count from the executor and does not delete evidence/entities/qualifications; checkpoint counting belongs to the worker implementation.

Verification: **33 tests passed** in the owned persistence/storage/lifecycle suites, including **5 new actual PostgreSQL integration tests** and **2 lifecycle unit tests**. New tests demonstrate retained saved qualifications after a budget stop, persisted partial reason/stage and terminal timestamp, atomic state/event commit/rollback, no direct-SQL terminal restart, exactly one concurrent finalizer winner with one terminal event, exhausted-versus-interrupted zero-result semantics, stage/version update, missing terminal-reason constraint rejection, and idempotent terminal outcomes. Existing persistence tests were adapted to expect automatically generated state events. Ruff and mypy pass for lifecycle and persistence source.

Public repository signature adds `expected_version` and `terminal_reason` to `JobRepository.transition`. Canonical completion reason is `terminal_reason='source_exhausted'`, not a separate `reason='exhausted'` parameter. Root-owned progress/API code was not edited. SKR-019 contracts are a dependency and must be independently verified before canonical ticket status becomes done.
